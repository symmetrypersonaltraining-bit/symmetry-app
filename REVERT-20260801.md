# Rollback — overnight build, 1 August 2026

Everything from tonight is revertable. Nothing was deleted; every migration is
additive or restores a previous value. Read this top to bottom before running
anything — the code and the database revert separately, and in most cases you
only need the code.

**Known-good point before tonight:** tag `pre-overnight-20260801` (commit `35b5511`).

---

## 1. Fastest: put the app back exactly as it was

```bash
git revert --no-edit 35b5511..HEAD   # keeps history, safe on a shared branch
git push origin main
```

Vercel redeploys on push. Takes about two minutes.

If you would rather move the branch itself (only do this if nobody else has
pulled):

```bash
git reset --hard pre-overnight-20260801
git push --force-with-lease origin main
```

## 2. Revert one thing, not everything

Each commit is self-contained and can be reverted on its own:

```bash
git log --oneline pre-overnight-20260801..HEAD   # list tonight's commits
git revert --no-edit <sha>                       # undo just that one
git push origin main
```

## 4. What is NOT touched, and cannot be broken by a revert

The calendar sync is untouched by tonight's work. These are exactly as they
were, and no revert is needed for any of them:

`gcal_sync_appointments`, `gcal_reconcile_appointments`,
`gcal_reconcile_payments`, `gcal_sync_payments`,
`gcal_generate_payment_notifications`, `recalc_pending_payment_reminders`,
`sync_supervised_workouts_to_appointments`, `detect_schedule_changes`, the
`appointments` schema, and the Central-time handling.

The one change in that area is that `gcal_get_clients()` now excludes archived
clients, so archiving someone actually stops the sync re-matching their events.
To undo just that:

```sql
create or replace function public.gcal_get_clients()
returns table(id uuid, name text)
language plpgsql security definer set search_path to 'public'
as $$ begin return query select c.id, c.name from clients c order by c.name; end; $$;
```
