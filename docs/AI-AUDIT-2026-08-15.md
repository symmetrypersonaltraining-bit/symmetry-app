## 1 · Accuracy — the fault worth caring about

`src/lib/ai/workoutAdjust.ts` counted database writes it never checked:

```
await db.from("prescribed_exercises").delete().eq("id", id); applied++;
```

Five places. A refused write and a successful one produced the same output —
*"Applied 3 changes"* — over a workout that had not changed.

This is the same class as the Bobbie Page incident earlier the same day, where
the coach invented a history ("you logged the treadmill as a separate entry")
for a session that has no log at all. **Both are the AI stating something as
fact that the database contradicts.** That is the failure mode to keep hunting,
and it is not caught by tests that only check the happy path.

Both are fixed. The adjuster now checks every write and names partial failures;
the coach now reads 14 days backwards and is told to say "I can't find it"
rather than theorise.

## 3 · `coach_read` — a permanent false alarm, now silenced

CoachFocusCard was removed from ClientDashboard on 1 Aug with a good reason
recorded in the source: it restated the Focus line ClientWeekSummary already
showed, so clients read the same coaching twice in two different voices.

But the feature stayed in the registry **unflagged**, so the health page would
have reported it NEVER USED forever. The registry's own comment on the `dormant`
flag says why that matters:

> *"One permanent false alarm is all it takes for the page to stop being read,
> and the page only earns its place by being believed."*

Marked dormant. **The component and its route are now orphaned** — nothing
mounts `CoachFocusCard` and nothing calls `/api/coach/focus`. Worth deleting on
a future pass, but deleting live code at 10pm to tidy a report is not a trade I
will make unprompted.

## 4 · The near-miss, written down deliberately

`chat` showed 512 calls and $1.82 over 30 days and **is not in `AI_FEATURES`**.
On its face: an unmetered surface, uncapped, invisible to the health page, and
the single largest line of spend.

It is not. `chat` ran 31 Jul → 13 Aug; `coach_action` starts 13 Aug and runs to
now. A rename, with a clean handover on the same day.

I checked before writing it up. I have called five things early in the last two
days and this would have been the sixth — a fabricated crisis in the one area
you have said most clearly must be right.

**Minor real consequence:** 30-day cost queries grouped by feature show `chat`
as an unknown row. Cosmetic; the money is counted either way.

## 5 · What this audit did NOT cover

Stated plainly so the gaps are not mistaken for clean bills of health:

- **No live end-to-end run of each surface.** I read the registry, the routes,
  the callers and 30 days of real usage. I did not sit in the app and fire all
  25. That needs a browser session with a logged-in client.
- **Avatars/faces:** the existing `aiFaceEverywhere` guard covers this and it
  caught my own violation tonight (a sparkle standing in for the coach's face on
  the new limit screen). So the rule is enforced, but I did not visually verify
  each surface.
- **Model selection per surface:** not audited this pass.
- **Output quality:** not assessable from logs. The two accuracy faults found
  today both surfaced from real incidents, not from monitoring — which is itself
  the finding. There is no automated check that the AI's factual claims match
  the database, and both of today's faults would have been caught instantly by
  one.

**That last point is the recommendation I would make if you only take one thing
from this audit.**
