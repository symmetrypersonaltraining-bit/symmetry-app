Root cause

Three places a food’s macros come from, and two of them let the model invent the number

PathWhere the numbers come from

Photo The model states calories, protein_g, carbs_g, fat_g itself. No catalogue lookup anywhere in the route.
The AI chat
“I ate a banana”, “swap M4 for wings”		 Its prompt says, in these words: “Estimate realistic macros per item (grams protein/carbs/fat, kcal).” No catalogue lookup.

The typed path was rebuilt on 26 Aug for exactly this reason. Its own header records why:

The parse prompt used to ask it to estimate macros using USDA / nutrition-label knowledge, which is recall plus arithmetic, and it got both wrong in ways that looked right.

That prompt is still live in the other two paths — and the chat one is the path you asked me to look at.

Worse: the chat path keeps the invented number. A swap calls saveMyMeal(), so a macro the model made up is written into that client’s My Meals library and re-used every time they pick it again.

Why no arithmetic check can ever catch this

All 154 client-saved foods are internally consistent — kcal agrees with 4/4/9 of their own macros, every single one. The banana row reading 242 kcal · 2P · 27C · 14F is perfectly self-consistent. It just isn’t a banana. A fabricated macro is consistent by construction. Only reading it off a row can catch it.

08
Better than it looks

What happens when you tell the AI to do something

Worth writing down plainly, because the control flow is sound:

  • Eight actions: swap a meal, add to a meal, move, copy, delete, add a snack, log, un-log.
  • Nothing changes until you tap Confirm. The reply comes back as a message plus a confirmation card; the write only runs on the tap, and a failure says so and changes nothing.
  • It never guesses which meal you meant. A reference it can’t resolve — missing, or two plausible matches — downgrades the whole action to one clarifying question.
  • Every write goes to the day on screen, and every label names that date when it isn’t today.

The gap isn’t here. It’s finding 01: what it asks you to confirm can contain a number nobody sourced.

Six calls, then we walk the buttons

Each one is a decision, not a preference — say yes or say different and I’ll build it.

1

Route photo and chat macros through the food databaserecommended

You added the important half: “if it’s not in the data base they need a way to search in online through ai and get real numbers.” So on a miss the app now goes to USDA FoodData Central, pulls the real measured rows, and the model chooses between them — it is never asked for a figure. What it picks is written into the catalogue with its USDA id, so the next client to eat it gets it with no network at all. The catalogue teaches itself.

The chat is done. The photo route is the last path still stating its own macros and is first up next session; the design is written out in the handoff.

A food only enters the library once it resolves to a real row. Otherwise one invented number becomes a permanent one.

Drop the badge from the 442,891 manufacturer-label rows and keep it for USDA core, USDA generic and your own trainer rows. Cronometer’s version is stronger: show the origin instead of a tick — “USDA” / “your library” / “from a label”. That takes a design pass, so it’s yours to pick.

The same 3% / 5 g check the AI builder already runs, printed on the trainer’s plan screen. Six live plans would flag today, five of them on fat.
